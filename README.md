# 装修群聊情感分析与风险预警系统

面向装修公司业主群场景的中文多任务文本分类项目。系统计划从结构化群聊文字消息中识别业主情感、装修风险类别和风险等级，并将高风险结果接入后续告警链路。

> 当前状态：项目环境和产品方案已建立，合成预标注候选数据仅保存在本地；模型下载、数据复核、训练、评测和业务链路仍在开发中。

## 项目目标

模型采用共享 Encoder 与三个分类头，同时输出：

- 情感：正面、中性、负面；
- 风险类别：恶意增项、工期拖延、偷工减料、材料以次充好、合同陷阱、售后失联/推诿、定金/停工威胁、无风险、其他风险；
- 风险等级：低、中、高。

产品遵循“少推送、不少记录”的原则：低、中、高风险结果均计划写入数据库，仅高风险结果进入即时告警链路，高风险告警优先保证精确率。

## 技术路线

- 基座模型：`hfl/chinese-roberta-wwm-ext`；
- 模型结构：共享 Encoder + 情感、风险类别、风险等级三个分类头；
- 训练框架：PyTorch、Hugging Face Transformers；
- 开发方式：Jupyter Notebook；
- 环境管理：uv + Python 3.11；
- 评测方向：提示词基线、模型微调效果与高风险告警效果；
- 后续业务集成：MySQL、n8n Webhook、企业微信告警。

## 数据说明

当前数据为装修场景合成数据，不是真实企业微信群聊记录，也不得描述为真实业务数据。

- 本地训练候选集：2,000 条大模型生成的预标注对话段；
- 本地测试候选集：200 条独立生成的预标注样本；
- 两份数据均需经过人工复核后，才能分别进入正式训练/验证数据和锁定测试集；
- `data/` 已加入 `.gitignore`，数据文件不会提交到仓库。

## 输入与聚合设计

模型输入计划由“最多两个历史对话段 + 当前对话段”组成：

```text
结构化群聊消息
  → 按群维护消息缓冲区
  → 静默 2 分钟 / 当前段达到 300 tokens / 持续 5 分钟时结束
  → 向前读取最近两个已结束对话段
  → 截断为不超过 450 tokens 的模型输入
  → 三任务分类
```

上下文只辅助判断，三项标签均针对当前对话段。

## 本地环境

同步依赖并进入项目环境：

```bash
uv sync
source .venv/bin/activate
```

注册 Notebook 内核：

```bash
uv run python -m ipykernel install \
  --user \
  --name risk-monitoring \
  --display-name "Python (risk-monitoring)"
```

在 Notebook 中确认解释器：

```python
import sys
print(sys.executable)
```

输出路径应指向项目内的 `.venv/bin/python`。

## 评测计划

所有方案使用同一份人工复核并锁定的测试集，主要记录：

- 三个分类任务各自的 Accuracy、Macro-F1 和混淆矩阵；
- 三项标签同时预测正确的联合准确率；
- 高风险 Precision、错误告警数量和漏掉的高风险数量；
- 推理耗时以及固定硬件环境下的吞吐和延迟。

测试集不参与训练、调参或 Few-shot 示例选择。
